## Три отдельных расчёта [SRC-093–097]

Профиль державы содержит относительные веса предложения. Он не хранит склад тонн, выработку за год или удовлетворённую потребность населения. Отправка не уменьшает профиль, ресурсную метку или население. Партия имеет физическую массу qty и условную стоимость val. Потоки держав/мира появляются при доставке. Казна, ВВП и st.trade цивилизационного ядра рассчитываются отдельно; прибытие судна платит по длине рейса, независимо от стоимости его товарных партий. Это подтверждено T64/T69 [SRC-096, SRC-100].

Есть отдельное изменение казны в _trade.rob: ограбление снижает средства и торговлю державы-перевозчика. Поэтому комментарий в начале trade.js о чисто описательной модели имеет это исключение. Деньги прогулки также не равны val: добыча переводится через местную дневную плату и логарифм стоимости [SRC-098].

## Биомы и источник предложения [SRC-094]

TRADE_BIOME задаёт только 15 перечисленных базовых ключей; остальные биомы не получают эти промыслы, но могут дать побережье, холм, ресурсную метку. Таблица не моделирует климат целиком.

| Биом | Базовые доли товаров |
| --- | --- |
| mangrove | fish=0.8, timber=0.3 |
| marsh | fish=0.4, hides=0.4 |
| tundra | furs=1, hides=0.4 |
| borealForest | furs=0.9, timber=1, hides=0.4 |
| coldDesert | livestock=0.6, salt=0.5 |
| temperateGrassland | grain=1, livestock=1, hides=0.6 |
| temperateDeciduous | grain=0.8, timber=0.8, hides=0.4, furs=0.3 |
| temperateRainforest | timber=1, furs=0.3 |
| mediterranean | wine=1, grain=0.6, livestock=0.4 |
| subtropicalDesert | salt=1, livestock=0.3 |
| savanna | livestock=0.8, hides=0.8, spices=0.3, grain=0.4 |
| tropSeasonalForest | spices=1, timber=0.7, grain=0.4 |
| tropRainforest | spices=1, timber=0.9 |
| alpine | livestock=0.7, flint=0.6 |
| barrenRock | flint=1 |

Клетка участвует при pop≥250 и !isWater. Основа B=√pop. Сначала берутся биомные raw, затем добавляются прибрежные fish/salt и холмистый flint. Холм: volcanic>.15 либо (elev−seaLevel)/(1−seaLevel)>.35. Прибрежная рыба — max биомной доли и .3+.7·min(1,maxFish); maxFish берётся только из четырёх ортогональных водных соседей. Даже при нулевой рыбе остаётся .3. Соль получает долю .4 на побережье при tempSmoothed>16.

Модификаторы: grain·(.3+fertility), timber·(.3+veg), hides·(.5+herb), livestock·(.6+.4·herb). Если сумма raw-долей S>1, вклад каждого равен B·доля/S, иначе B·доля. Метка недр отдельно добавляет 4·(B+30), не делит этот бюджет. Добыча требует эпоху RES.era и соответствующее inv, если оно есть.

Город — строго urban>2800, pop>11000 и суша. При n доступных craft каждый получает √min(urban,pop)·1.2·2/(1+n); ind дополнительно ·(.15+min(industry,2)). Вклад суммируется по клеткам. Для выбора единственного лучшего места городской балл утраивается; сумма предложения не утраивается. Поэтому «делают в этом городе» означает город при лучшем источнике товара, а не полный список производств.

Обход фиксирует технологические маски и uid держав на старте. Строк за тик max(1,ceil(H/8)), после публикации ожидание max(0,24−8). При высоте, не кратной полосам, полный цикл может отличаться от 24. UID предотвращает публикацию старого профиля новой державе в том же слоте. profileOf немедленно строит профиль новой uid по st.cells; рост населения/смена технологий прежней uid ждут нового обхода. pickGood повторно проверяет canMake. Город у источника ищется в радиусе CITY_R=8, город погрузки/прибытия — 3; квадрат расстояния сравнивается с r²+.5.

Выбор товара при профилях a продавца и b покупателя имеет вес:

```text
a · price^.4 · (1 − .75 · min(1,b/a))
```

Нужно a>0, действительное место производства, canMake и canUse. Даже b≥a оставляет четверть базового спроса. canUse допускает inv при tech+2.5; отсутствующий покупатель пропускает этот барьер. Генератор rnd хеширует worldSeed, simTick, собственный растущий _rs и соль, не расходует Math.random. Сброс возвращает _rs=0; обычный save его не сохраняет [SRC-093–095, SRC-099, SRC-100].

## Запись партии и ограниченная память [SRC-095]

Пул 768 слотов циклически заменяет любой слот кроме GO и явно защищённого источника перепродажи. Все в пути — новая партия не создаётся. Сквозной id растёт отдельно; старый slot не является прежним id. Typed arrays хранят состояние/товар/перевозчика, qty/val, происхождение p*, последнюю погрузку l*, владельца перевозчика oUid, покупателя d*, ETA/доставку, путь/направление, prev/next, причину/захватчика и до четырёх hops. Имена городов/держав фиксируются отдельно от uid и нынешних объектов.

Новая масса max(.01,cap·share·qk·(.6+.4·rnd)), val=qty·price. Исходная дата производства искусственно сдвинута назад на (.1+1.4·rnd) лет, для craft вдвое меньше. Это метаданные происхождения, не отыгранная производственная операция. Производитель, последний продавец, перевозчик и текущий покупатель могут быть разными державами.

| Состояние | Значение и запись |
| --- | --- |
| FREE=0 | Свободный слот |
| GO=1 | В пути; слот защищён от повторного использования |
| DONE=2 | Доставка; потоки/истории/покупатель записаны |
| LOST=3 | Потеря: LOST_WAR=−2 или LOST_GONE=−3 |
| TAKEN=4 | Каперство; by=uid захватчика |
| ROBBED=5 | Ограбление игроком; by=BY_PLAYER=−4 |

Прикреплённая к живому судну GO ждёт реального перехода судна в следующий рейс или удаления после прибытия, даже если ETA прошёл. Отцепленная партия доставляется dueTick при ETA≤текущего года. arrive(id) разрешает раннее прибытие с прогулки; повторный вызов после конца возвращает null. Результат войны проверяется лишь при доставке сухопутного car<6 между живым последним продавцом и владельцем назначения. Морские/воздушные партии не используют этот конкретный барьер.

Доставка определяет нынешнего владельца клетки назначения, а исходный снимок технологии покупателя iT сохраняет. Если владелец исчез, dUid=−1. Если последний продавец и текущий получатель различны, записываются экспорт/импорт; при ничейной клетке возможен лишь экспорт. Домашняя поставка всё равно увеличивает путь, мировой оборот и кольцо покупателей. Проверка войны выполняется перед DONE. Потеря/захват/ограбление увеличивает lost пути и отдельный мировой счётчик, без доставленного оборота [SRC-097–100].

## Перепродажа [SRC-095, SRC-100]

findReexport ищет DONE, полученную нынешним продавцом за границей: продавец не первоначальный производитель и не последний загрузчик; next=0; возраст от .15 до 25 лет включительно. Покупатель существует и отличается от продавца/производителя/последнего загрузчика, умеет использовать товар. И покупатель, и продавец исключены из сохранённых hops. Для моря прежняя клетка доставки не дальше двух клеток по каждой оси от погрузки. Выбирается самая недавняя доставка.

Создаётся новая партия с прежними p*, qty=max(.01,min(прежняя qty,cap·qk)), новым продавцом/перевозчиком/получателем. В hops добавляется предыдущий покупатель с датой и местом; при переполнении удаляется самое старое звено. val=qty·price·(1+.15·число сохранённых hops). При четырёх звеньях множитель достигает 1.6 и дальше не растёт. prev/next связывают id; источник можно отправить дальше только раз через обычный поиск.

**Масса источника не уменьшается.** Отправленная часть ограничивается вместимостью, остаток отдельной партией не выдаётся. Полная история посещённых держав не хранится: запрет повторов видит производителя, последнего продавца и сохранённые hops. Утраченные старые звенья не доказывают бесконечного запрета возврата. Внутренняя reexport сама проверяет только DONE/свободный слот; остальные фильтры — у вызывающего findReexport.

При морской перепродаже первая партия может занять полную cap, после чего второму товару выделяется ещё .4·cap. Вместе масса может превышать номинальную вместимость. T66 воспроизводит этот случай с искусственной cap=1 и вероятностями=1. При обычных двух свежих товарах доли .6/.4; qk и случайность дополнительно меняют массы. Это описание ветвей поставки, не исправление игровых правил.

## Потоки, пути и город [SRC-097]

Товарный route хранит доставленные n/qty/val, потерянные lost, активные go, затухающие rate и fl[g·4+направление·2], историю sr. Морской ключ объединяет упорядоченную пару портов: 1+a·N+b. Сухопутный — пару uid: −(1+minUid·2097152+maxUid); его концы отображают нынешние столицы. Маршрут создаётся до успешного выбора груза, поэтому возможна запись без поставок. Новый вытесняет слабейший незанятый маршрут по rate и признаку прежней доставки; занятые защищены. ROUTE_FORGET=80 применяется строго при idle>80 и go≤0.

Статистика державы привязана к uid и содержит ex/im[g·2+масса/стоимость], накопленные tEx/tIm и число поставок. У мира — wQ/wV и незатухающие итоги q/v/n/lost/taken/robbed. При **каждом вызове годового обработчика** текущие fl/rate/ex/im/wQ/wV умножаются на k=.5^(1/6). Скачок на много лет даёт одну операцию затухания; T47 — искусственный прямой вызов. UI показывает acc·(1−k) «в год», а не точное скользящее окно. Затухание не меняет итоговые суммы и массы отдельных партий.

История имеет 48 точек с начальным шагом 2 года. При достижении next пишется одна точка за вызов: накопленное количество/стоимость делятся на max(.5,year−y0). Полный ряд усредняет соседние пары, берёт более позднюю дату, удваивает шаг. Государственный ряд использует две стоимости экспорта/импорта, хотя поля называются aq/av. Кольцо каждого товара хранит 24 последних покупателей отдельно от циклического пула партий.

Карточка города статически читает:

- «делают здесь»: товары опубликованного профиля нынешней державы, у которых единственный выбранный city равен клетке города;
- пути: суша по точному концу-столице, море по порту не дальше трёх клеток по осям и приписанному городу; сортировка по rate, первые 12;
- «отправлено»: любые сохранённые партии с lCity/lCell города, первые 12 в списке; общий sent считает весь оставшийся пул;
- «везут»: только GO с dCity/dCell города, первые 12. KPI берёт длину уже обрезанного списка, поэтому максимум 12, как и счётчик путей.

Это не полный городской бухгалтерский журнал: старые слоты заменяются, а несколько мест производства сведены к одному лучшему источнику. DOM/окна не отрисовывались; T01 проверяет загрузку UI-замыкания, не визуальный результат [SRC-100].

## Сохранение и точное продолжение [SRC-099]

Обычный ext.trade v1 содержит keys товаров, seq/rid/ypt, интернированные names, L/R/S/G/W. qty/val/потоки/технологии округляются до двух знаков, даты до четырёх, ypt до семи. Для GO на судне ETA вычисляется заново только для сейва, не меняя живой пул. Судовые ссылки не записываются. После reset/load восстановленные партии продолжают по сроку без своего судна; RNG, landAcc и прогресс обхода не восстанавливаются. scanAll выполняется сразу.

Загрузка сопоставляет товары по key, сохраняет в пределах пула самые новые входные L по id, пропускает неизвестные товары/невалидные записи, ограничивает маршруты и строки имён (120 символов). route.go пересчитывается по GO, rate — по загруженным fl; геометрия пути приходит отдельно/строится заново. Слишком малые округлённые массы могут потерять точность; не считать загрузчик строгой проверкой всех экономических инвариантов.

netGet/netSet передают точные массивы, имена, ссылки cShip/trk, RNG/seq, скан и профили, города по слотам, маршруты/карты, landAcc, истории/мировые итоги, часы. netSet проверяет тип/длину основных пуловых массивов и возвращает связи контейнеров; это не валидация всех вложенных значений. netSnapshot кодирует одним графом со states/ships, после обычной загрузки netApplySnapshot возвращает точное состояние. T54 проверяет адаптер с сохраняющим ссылки клоном внутри VM, T55 — отказ по неверной длине основного массива. Реальная кодировка/передача/комната не проверены.

Reset очищает товарное состояние, но сам не удаляет _tr*-метки у внешне сохранённых объектов судов. T67 намеренно удерживает старые ships и показывает отсутствие повторной загрузки; обычный сброс ядра отдельно убирает ships. Это искусственная граница вызова, не наблюдение штатного сбоя.
